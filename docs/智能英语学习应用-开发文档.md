## 1. 项目概述

### 1.1 一句话定义

用户上传任意格式的英语材料（PDF / 扫描件 / DOCX / MD / TXT / 图片），系统把文档「翻译」成一份**老师批改过的手账**——原文被荧光笔、红圈、波浪线、手写批注重新覆盖，所有标记的**数量、难度、讲解深度都由用户选定的能力水平（高中 / 四级 / 六级 / 考研 / 雅思 / 托福）动态决定**，并支持一键导出为 PDF / 长图 / 打印稿。

### 1.2 解决什么问题

| 现状痛点 | 本产品的解法 |
|---|---|
| 读外刊/真题时不知道该圈哪些词，划满了等于没划 | 按等级自动区分「已掌握词」与「超纲常考词」，只圈后者 |
| 长难句看不懂，查语法要来回切 App | 直接在句子上叠加语法结构标记 + 中文批注 |
| 背了模板句却不知道哪句能用在作文里 | 加分句型用专属标记（红色波浪线 + 便利贴）标出并注明用途 |
| 笔记散落在各个平台，复习不方便 | 一键导出为可打印的手账 PDF，或生成长图分享 |
| 市面工具要么只查词、要么只翻译，缺少「按水平自适应」 | 六档能力模型驱动标注密度与讲解深度，同文不同标 |

### 1.3 核心功能清单（Feature Map）

| 编号 | 功能 | 优先级 |
|---|---|---|
| F1 | 多格式文件上传与解析（PDF / DOCX / MD / TXT / 图片 / 扫描件） | P0 |
| F2 | 图文智能扫描：正文提取 + 版面还原 + 图表/插图的语义识别 | P0 |
| F3 | 能力水平选择（6 档）与切换 | P0 |
| F4 | 手账生成引擎：「涂改式」语法标注 + 重点词圈选 + 加分句型标注 | P0 |
| F5 | 一键导出（PDF / PNG 长图 / 打印版式 / Word） | P0 |
| F6 | 大模型 API 接入（多厂商适配 + 用户自带 Key） | P0 |
| F7 | 手账阅读器（缩放、翻页、点击标注查看解析） | P1 |
| F8 | 生词本 / 句型本 / 错题本，艾宾浩斯复习计划 | P1 |
| F9 | 手动补标与编辑（用户自己加圈、改批注） | P1 |
| F10 | 历史文档管理、标签与检索 | P1 |
| F11 | 分享链接 / 学习小组 | P2 |
| F12 | 语音朗读、跟读评分 | P2 |

### 1.4 目标用户与典型场景

- **备考学生**（高中/四六级/考研）：上传真题阅读，生成「只圈超纲词」的精读稿。
- **雅思托福考生**：上传 Economist / 原版教材，标注高级句型与学术词汇。
- **英语老师**：上传课文或试卷，生成标准化的讲解手账发给学生。
- **自学者**：随手把手机拍的英文材料（菜单、说明书、论文截图）变成学习手账。

### 1.5 术语表

| 术语 | 含义 |
|---|---|
| **原始文档（Source）** | 用户上传的任意格式文件 |
| **区块（Block）** | 文档解析后的最小可标注单元（段落 / 标题 / 图注 / 表格单元格 / 图片） |
| **手账（Handbook）** | 一个文档 + 一个等级 + 一套标注，生成的渲染结果集合 |
| **涂改层（Markup Layer）** | 叠加在原文之上的可视化标注容器（SVG 矢量层） |
| **等级画像（Level Profile）** | 某一能力档位的参数集合，驱动标注策略 |
| **标注（Annotation）** | 一次具体的标记行为：圈选、荧光、波浪线、批注、印章…… |
| **超纲词（Overflow Word）** | 超出当前等级词表范围、且属于该等级高频考点的词 |

## 2. 需求分析

### 2.1 功能需求（FR）

#### FR-1 文件上传与解析

- **FR-1.1** 支持格式：`.pdf`（文字层/扫描件）、`.docx`、`.doc`、`.md`、`.txt`、`.png/.jpg/.jpeg/.webp/.heic`、`.epub`（P2）。
- **FR-1.2** 单文件 ≤ 100 MB，PDF 页数 ≤ 300 页；支持批量上传（≤ 20 个）。
- **FR-1.3** 上传后 3 秒内返回预览（首页缩略图 + 页数 + 预估处理时长）。
- **FR-1.4** 解析失败要给出明确原因（加密 PDF / 纯图片无 OCR 权限 / 编码异常）并提供降级路径。

**验收标准**：上传一份 30 页的扫描版雅思阅读，能在 90 秒内完成全部解析与标注，页面文字识别准确率 ≥ 96%（英文印刷体）。

#### FR-2 图文智能扫描

- **FR-2.1** 版面分析：识别标题 / 正文 / 分栏 / 表格 / 图注 / 页眉页脚 / 脚注。
- **FR-2.2** 双栏排版必须正确还原阅读顺序（左栏读完再读右栏）。
- **FR-2.3** 图片处理：插图调用多模态模型生成一句话描述（"这张图展示了 2000–2020 年全球碳排放趋势，纵轴单位是十亿吨"），并作为图注参与后续语境理解。
- **FR-2.4** 表格：转为结构化数据，保留行列表头。

#### FR-3 能力水平选择

- **FR-3.1** 首次使用需选择等级；可在文档详情页随时切换。
- **FR-3.2** 切换等级触发「重新标注」，支持增量：已标注结果按等级缓存，切换时优先命中缓存。
- **FR-3.3** 提供「自定义等级」（P2）：用户可微调词汇量阈值、标注密度。

#### FR-4 手账生成引擎

- **FR-4.1 语法涂改**：对句子中的目标语法结构，用彩色下划线 + 括弧 + 手写批注标注，注明结构名称与作用。
- **FR-4.2 重点词圈选**：用椭圆圈 + 荧光笔标记超纲高频词、熟词僻义、固定搭配；带音标与一句中文释义（悬浮显示）。
- **FR-4.3 加分句型**：用红色波浪线标记作文可用句型，右侧便利贴注明「可用于：议论文开头 / 图表描述 / 观点转折」。
- **FR-4.4 长难句图解**：超过阈值的句子自动折行 + 缩进展示主干与修饰成分。
- **FR-4.5 中式表达纠错**：对用户自行写的作文（P2 输入模式），用「涂改 + 重写」的方式给出地道表达。
- **FR-4.6** 标注密度受控：同一段落标记不超过 N 处，避免"划满等于没划"。

#### FR-5 一键导出

- **FR-5.1** 导出格式：PDF（矢量、可搜索文本层）、PNG 长图、打印优化版（A4 双栏 / 留白装订边）、DOCX（可再编辑）。
- **FR-5.2** 导出选项：是否含答案、是否含生词表、是否含原文底纹、是否含手写字体。
- **FR-5.3** 导出任务异步执行，完成后站内通知 + 下载链接（有效期 7 天）。

#### FR-6 大模型 API 接入

- **FR-6.1** 内置默认模型（平台承担成本，按次计费/会员制）。
- **FR-6.2** 支持用户自带 Key（BYOK）：OpenAI、Azure OpenAI、DeepSeek、通义千问、智谱、Anthropic、Gemini、Groq、以及任意 OpenAI 兼容端点（含本地 Ollama / vLLM）。
- **FR-6.3** 支持「任务分流」：解析类小任务用便宜模型，语义标注用强模型，图片理解用多模态模型。
- **FR-6.4** 提供调用日志、Token 消耗统计、失败重试与降级。

#### FR-7~FR-12

阅读器、生词本、手动编辑、历史管理、分享，详见 [第 10 章](#10-前端设计)。

### 2.2 非功能需求（NFR）

| 类别 | 指标 |
|---|---|
| 性能 | 文字层 PDF 单页标注 ≤ 3 s；扫描件单页 ≤ 6 s；P95 首屏渲染 ≤ 1.5 s |
| 并发 | 单实例支持 50 并发上传、200 并发读取；Worker 水平扩展 |
| 可用性 | 核心接口 99.5%；LLM 供应商故障时自动切换备用通道 |
| 可维护性 | 前后端分离；解析器、渲染器、LLM 适配器均为插件式可替换 |
| 成本 | 单篇 2000 词文章的标注成本目标 ≤ ¥0.15（使用国产中端模型） |
| 兼容 | Chrome / Edge / Safari 最新两个大版本；移动端响应式（手账以横屏/缩放阅读为主） |
| 国际化 | 界面中英双语；讲解语言可选中文 / 英文 / 双语 |
| 无障碍 | 标注不仅靠颜色区分，同时有形状差异（色盲友好） |

### 2.3 用户故事示例

> **US-01**　作为一名备考六级的同学，我希望上传一篇 The Economist 文章后，系统只圈出六级以上的高频词，这样我不用在每个生词上浪费时间。
> **验收**：随机抽 50 个被圈选的词，人工判定"确实超出六级范围"的比例 ≥ 85%。

> **US-02**　作为一名雅思写作 5.5 分的考生，我希望文章里的好句型被单独标出来，并告诉我能用在小作文的哪个部分。
> **验收**：每篇 ≥ 1500 词的文章至少标出 5 个句型，且用途分类准确率 ≥ 80%。

## 3. 能力分级体系（核心设计）

这是整个产品的**护城河**。同一篇文章，选「高中」和选「托福」，出来的手账应该是两份完全不同的材料。

### 3.1 六档能力模型

| 等级 ID | 名称 | 词汇量基准 | 词汇表来源 | 语法覆盖范围 | 典型材料难度 |
|---|---|---|---|---|---|
| `high_school` | 高中 | 3500 | 课标 3500 / 高考考纲 | 时态语态、三大从句、非谓语基础、常见固定搭配 | 高考阅读 C/D 篇 |
| `cet4` | 大学四级 | 4500 | CET-4 大纲词汇 | 非谓语进阶、虚拟语气基础、倒装基础、强调句 | 四级仔细阅读 |
| `cet6` | 大学六级 | 6000 | CET-6 大纲词汇 | 全部基础语法 + 复杂从句嵌套、独立主格 | 六级长篇阅读 |
| `kaoyan` | 考研 | 5500（+派生） | 考研英语大纲 | 长难句拆分、插入语、省略、倒装、比较结构 | 考研英语一 Text 1–4 |
| `ielts` | 雅思 | 8000（A 类） | Oxford 5000 + AWL 学术词表 | 学术写作句型、图表描述结构、复杂名词化 | 雅思阅读 Passage 3 |
| `toefl` | 托福 | 10000 | TOEFL 核心 + AWL | 学术长难句、抽象概念表达、逻辑连接 | TOEFL Reading 学术论文 |

> 说明：词汇量是**近似基准**，实际判定以「词表集合运算 + CEFR 标签 + 语料频次」三者加权为准，见 [6.3](#63-语言分析层linguistic-analysis)。

### 3.3 标注策略矩阵（同文不同标的示例）

以句子 *"Not until the committee had reviewed all the submissions did they realize how flawed the methodology was."* 为例：

| 等级 | 圈选单词 | 语法标注 | 批注深度 | 加分句型 |
|---|---|---|---|---|
| 高中 | `committee`, `submission`, `flawed`, `methodology` | 标「Not until 引导的部分倒装」+ 中文解释 | 完整中文讲解 + 还原为正常语序 | 否（超纲） |
| 四级 | `submission`, `flawed`, `methodology` | 标倒装结构名称 + 一句提示 | 中文简释 | 是，标「可用于议论文强调」 |
| 六级 | `flawed`, `methodology` | 只标下划线 + 结构名 | 英文短语注释 | 是，标「高级倒装，写作加分」 |
| 考研 | 仅 `methodology` | 标下划线，不解释 | 无批注（视为已掌握） | 是 + 仿写提示 |
| 雅思/托福 | 无（视为已掌握） | 不做语法标注 | 无 | 标为「学术写作可用句型」 |

这张表就是标注引擎的**行为规格说明（behavior spec）**，后续所有测试用例都从它派生。

### 3.4 等级判定的三个信号源

```
最终难度分 = w1 × 词表集合差  +  w2 × CEFR 标签  +  w3 × 语料频次分位
             (0.45)              (0.35)             (0.20)
```

- **词表集合差**：单词是否在目标等级词表内（含词形还原后的原形匹配）。
- **CEFR 标签**：Oxford 5000 的 A1–C2 分级；C1/C2 词在低等级中必然被圈。
- **语料频次分位**：基于 COCA / BNC 的 Zipf 频率（`zipf_frequency`），频率 < 3.5 视为低频词。

### 4.2 技术选型与理由

| 层次 | 选型 | 理由 |
|---|---|---|
| 前端框架 | **Next.js 14（App Router）+ TypeScript** | SSR 利于首屏；类型安全；生态成熟 |
| 样式 | Tailwind CSS + CSS Variables | 快速实现主题化（手账风格换肤） |
| 状态管理 | Zustand | 轻量，适合阅读器这类局部状态密集场景 |
| 手账画布 | **HTML/CSS 为主 + SVG 标注层 + Fabric.js（可编辑模式）** | HTML 便于文本流排版与无障碍；SVG 便于矢量涂改笔画 |
| 后端语言 | **Python 3.11 + FastAPI** | NLP/OCR/文档解析生态（PyMuPDF、PaddleOCR、spaCy）碾压 Node |

### 5.3 关键设计决策

| 决策 | 方案 | 理由 |
|---|---|---|
| 是否整篇送 LLM | **否**，本地 NLP 先筛候选 | 省 70%+ token；避免模型注意力稀释 |
| 标注结果缓存键 | `sha256(file) + level_id + prompt_version` | 同一文档换等级可秒出；提示词升级可自动失效 |
| 分块策略 | 按语义段落切（≤ 800 token），带前后各 1 段上下文 | 保持上下文完整性，避免句子被切断 |
| 进度反馈 | SSE（而非 WebSocket） | 单向推送足够，实现简单，穿透代理好 |
| 失败降级 | LLM 超时 → 退化为「纯规则标注」 | 保证有产出，不白跑 |

## 6. 关键模块详细设计

### 6.1 文档解析层（Parse）

#### 6.1.1 PDF 分流策略

```python
def parse_pdf(path):
    doc = fitz.open(path)
    text_len = sum(len(p.get_text("text")) for p in doc)
    if text_len / len(doc) < 100:      # 平均每页少于 100 字符 → 判定为扫描件
        return parse_scanned_pdf(path)  # 走 OCR 通道
    else:
        return parse_text_pdf(path)     # 走文字层通道
```

- **文字层 PDF**：PyMuPDF 抽取 `(text, bbox, font, size, block_type)`。用字号聚类识别标题层级。保留 bbox 供"原文叠加模式"定位。
  > ⚠️ 实现变更：改用 **pypdfium2**（AGPL 风险），它只提供字符框，因此字号改用
  > **行宽 ÷ 等效字符数**，版面聚类由自研 `layout.py` 负责。见 4.2 节的变更表。
- **扫描件 PDF / 图片**：PaddleOCR（`ch` + `en` 混合模型）→ 文本行 + 四边形坐标 → 版面分析模型（或基于坐标的启发式）聚类为段落 / 分栏。
  > ⚠️ 实现变更：OCR 用 **RapidOCR**（Apache-2.0，onnxruntime 后端）；
  > 版面聚类不依赖模型，用**中缝检测 + 递归切栏 + 行距基准（pitch）分段**的启发式实现，
  > 与文字层共用同一套 `layout.build_blocks()`。
- **表格**：pdfplumber `extract_tables()`；扫描件用 PP-Structure 的表格恢复能力。

#### 6.1.2 统一中间表示（IR）

所有 Parser 必须输出同一结构，这是插件化的基础：

```python
@dataclass
class Block:
    id: str
    type: Literal["title", "paragraph", "list", "table", "figure", "caption", "footnote"]
    order: int                      # 阅读顺序
    text: str | None
    page: int | None
    bbox: tuple[float, float, float, float] | None   # 归一化坐标 0~1
    level: int | None               # 标题层级
    image_ref: str | None           # 图片在对象存储中的 key
    image_desc: str | None          # 多模态模型生成的描述
    table_data: list[list[str]] | None
    meta: dict
```

#### 6.1.3 清洗规则清单

1. 删除重复出现的页眉页脚（跨页文本相似度 > 0.9）。
2. 合并行尾连字符断词（`metho-\ndology` → `methodology`）。
3. 双栏重排：按 bbox 的 x 中心聚类为栏，栏内按 y 排序。
4. 去除孤立页码、DOI、版权行。
5. 软连字符、非断行空格、零宽字符归一化。
6. 引号/撇号统一为 ASCII 或排版引号（按输出场景）。

### 6.3 语言分析层（Linguistic Analysis）

#### 6.3.1 处理链

```
raw text
  → 分句（spaCy sentencizer，处理缩写 "Dr." "U.S." 不误切）
  → 分词 + 词性 + 依存句法（en_core_web_trf）
  → 词形还原（lemminflect，处理不规则变化）
  → 词组识别（名词短语 NP、动词短语 VP、介词短语 PP）
  → 难度打分（见 3.4）
  → 语法结构识别
  → 候选筛选
```

#### 6.3.2 语法结构识别（规则 + 句法树模式）

不依赖 LLM 就能识别的结构（成本为零，准确率高），只有识别不出或需要讲解时才交给 LLM：

| 结构 | 识别信号 |
|---|---|
| 定语从句 | 依存树中存在 `relcl` 关系 + 关系代词（which/that/who/whose/where） |
| 状语从句 | `advcl` + 从属连词表（although/because/while/if...） |
| 名词性从句 | `ccomp`/`xcomp`/`acl` 且从句作主语/宾语/表语 |
| 非谓语 | 动词的 `VBG`/`VBN`/`VB` 形态出现在非谓语位置 |
| 虚拟语气 | 句式模板：`If + had + VBN`、`wish + past`、`were to`、`should have VBN` |
| 倒装 | 句首为否定副词（Not until/Never/Hardly/Seldom）+ 助动词前置 |
| 强调句 | `It is/was ... that ...` 模板 |
| 独立主格 | 名词/代词 + 分词，且无连词连接两个谓语 |
| 插入语 | 逗号/破折号包裹的 `parataxis` 或 `appos` |
| 比较结构 | `as...as`、`more...than`、`the more...the more` |

#### 6.3.3 候选筛选（省 token 的关键）

对每个句子计算 `annotation_value`，只有高于阈值的才进 LLM 队列：

```python
annotation_value = (
    0.30 * overflow_word_ratio      # 超纲词占比
  + 0.25 * log(sentence_length)/log(60)   # 句长（对数压缩）
  + 0.20 * grammar_structure_score  # 命中目标语法结构的加权分
  + 0.15 * pattern_match_score      # 命中句型模板
  + 0.10 * is_topic_sentence        # 是否段落主题句
)
# 阈值随等级浮动：等级越低阈值越低（低水平学生需要更多标注）
threshold = base_threshold[level]   # high_school 0.25 → toefl 0.55
```

实测预期：一篇 2000 词文章筛出 25–40 个待标注句，占全文 35%–50%，token 消耗降低 60% 以上。

#### 6.4.3 密度控制算法

防止"划满等于没划"，这是产品体验成败的关键：

```python
def apply_density_policy(annotations, profile, paragraph):
    # 1. 按优先级排序
    prio = {
        "sentence_pattern": 100,   # 作文加分句型永远保留
        "word_circle": 80,
        "grammar_underline": 60,
        "word_highlight": 40,
        "rare_meaning": 70,
    }
    annotations.sort(key=lambda a: prio[a.type], reverse=True)

    # 2. 单词类总量上限（按等级）
    word_cap = profile.markup_policy["word_circle_max_per_1000"] * len(tokens)/1000
    # 3. 单段上限 = ceil(段落句数 × grammar_mark_density) 且 ≤ 6
    para_cap = min(math.ceil(len(paragraph.sentences) * profile.markup_policy["grammar_mark_density"]), 6)
    # 4. 同句内相邻标注不重叠：若重叠，保留高优先级，低优先级迁移到边栏批注
    # 5. 返回裁剪后的结果
```

#### 6.4.4 标注输出 Schema（LLM 必须严格遵守）

```json
{
  "block_id": "b_012",
  "annotations": [
    {
      "type": "grammar_underline",
      "target_text": "did they realize",
      "start_offset": 88,
      "end_offset": 103,
      "grammar_id": "inversion",
      "label": "部分倒装",
      "explain": "Not until 置于句首时，主句要用部分倒装：助动词 did 提到主语 they 之前。正常语序为 they did not realize...",
      "confidence": 0.94
    },
    {
      "type": "word_circle",
      "target_text": "methodology",
      "lemma": "methodology",
      "pos": "noun",
      "phonetic": "/ˌmeθəˈdɒlədʒi/",
      "gloss_zh": "方法论；研究方法",
      "is_overflow": true,
      "level_tag": "C1",
      "memory_hook": "method（方法）+ ology（学科）→ 方法论",
      "confidence": 0.97
    },
    {
      "type": "sentence_pattern",
      "target_text": "Not until ... did ...",
      "pattern_name": "Not until 部分倒装",
      "usage": ["议论文强调", "图表作文转折"],
      "imitation": "Not until we understand the data can we draw a sound conclusion.",
      "confidence": 0.91
    }
  ]
}
```

> **实现要点**：`start_offset` / `end_offset` 必须由后端在原文中二次定位校验（`text[start:end] == target_text`），不匹配则用模糊匹配（difflib）修复或丢弃该条。**绝不信任模型的偏移量**。

#### 6.4.5 去重与合并

- 同一 `(type, start, end)` 重复 → 保留 `confidence` 最高者。
- 相邻且同类型的标注间隔 < 2 字符 → 合并。
- 单词标注与语法标注在同一 span 上共存时，视觉上错开（语法下划线画在单词下方，圈选用椭圆外扩 2px）。

### 6.5 提示词工程

提示词**版本化**存放于 `llm/prompts/{task}/v{n}.jinja`，变更即换版本号，缓存键自动失效。

#### 6.5.1 系统提示词（词汇标注任务 · 骨架）

```
You are an English teacher preparing a marked-up study handbook for a Chinese
student whose target level is {{ level.display_name }} (vocabulary baseline:
{{ level.vocab_baseline }} words).

RULES:
1. Mark ONLY words the student is unlikely to know at this level. Words within
   the {{ level.vocab_baseline }}-word baseline must NOT be marked, unless they
   are used in a rare/idiomatic sense.
2. For each marked word return: exact surface form, lemma, POS, IPA phonetic,
   a concise Simplified-Chinese gloss (<= 15 characters), whether it is
   "overflow" (beyond target level), and a memory hook if one exists.
3. Maximum {{ level.markup_policy.word_circle_max_per_1000 }} marked words per
   1000 words of text.
4. Never mark proper nouns, numbers, or the same lemma twice in one paragraph.
5. Output STRICT JSON conforming to the provided schema. No prose, no markdown
   fences.

CONTEXT: The text is from {{ source_hint }}. Domain: {{ domain }}.
```

#### 6.5.2 Few-shot 示例

每个任务在提示词中内置 2–3 个**已标注的黄金样例**（gold examples），显式展示"该标什么 / 不该标什么"。样例按等级切换（高中样例与托福样例不同）。

#### 6.5.3 输出约束手段（三重保险）

1. **结构化输出**：优先用厂商原生能力（OpenAI `response_format: json_schema`、Anthropic tool use、Qwen `response_format`）。
2. **Schema 校验**：Pydantic 校验，失败则把错误信息拼回提示词重试（最多 2 次）。
3. **兜底解析**：正则提取第一个 `{...}` 块；再失败则降级为规则标注。

#### 6.5.4 成本优化清单

| 手段 | 预期节省 |
|---|---|
| 本地 NLP 预筛候选句 | ~60% |
| 结果缓存（doc+level+prompt 版本） | 重复文档 100% |
| 小模型做分句/词性/翻译，大模型只做语义判断 | ~35% |
| 批量合并请求（一次送 3–5 个段落） | ~20%（减少 system prompt 重复） |
| 提示词精简（去冗余指令、用缩写标签） | ~15% |
| 用户 BYOK（用户自付） | 平台侧 100% |

### 7.2 核心表结构

```sql
-- 用户
CREATE TABLE users (
    id              BIGSERIAL PRIMARY KEY,

    password_hash   TEXT,
    display_name    TEXT,
    target_level    VARCHAR(32) NOT NULL DEFAULT 'cet4',

);

-- 文档
CREATE TABLE documents (
    id            BIGSERIAL PRIMARY KEY,
    user_id       BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    title         TEXT NOT NULL,
    source_type   VARCHAR(16) NOT NULL,          -- pdf/docx/md/txt/image
    storage_key   TEXT NOT NULL,                 -- 对象存储 key
    file_sha256   CHAR(64) NOT NULL,             -- 去重指纹
    page_count    INT,
    word_count    INT,

    parse_status  VARCHAR(16) NOT NULL DEFAULT 'pending',
    parse_error   TEXT,

CREATE INDEX idx_documents_sha  ON documents(file_sha256);

-- 文档区块
CREATE TABLE document_blocks (
    id          BIGSERIAL PRIMARY KEY,

    order_index INT NOT NULL,

    text        TEXT,
    page_no     INT,
    bbox        FLOAT8[4],
    image_key   TEXT,
    image_desc  TEXT,

-- 等级画像（配置化，便于运营调整）
CREATE TABLE level_profiles (
    level_id     VARCHAR(32) PRIMARY KEY,

    config       JSONB NOT NULL,
    version      INT NOT NULL DEFAULT 1,
    updated_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 分析任务
CREATE TABLE analysis_jobs (
    id             BIGSERIAL PRIMARY KEY,
    document_id    BIGINT NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    user_id        BIGINT NOT NULL REFERENCES users(id),
    level_id       VARCHAR(32) NOT NULL,
    prompt_version VARCHAR(16) NOT NULL,
    stage          VARCHAR(16) NOT NULL,           -- parse/analyze/render/export
    status         VARCHAR(16) NOT NULL,           -- queued/running/succeeded/failed
    progress       SMALLINT NOT NULL DEFAULT 0,
    message        TEXT,
    error          TEXT,
    tokens_in      INT DEFAULT 0,
    tokens_out     INT DEFAULT 0,
    cost_cents     INT DEFAULT 0,
    started_at     TIMESTAMPTZ,
    finished_at    TIMESTAMPTZ
);
CREATE INDEX idx_jobs_doc_level ON analysis_jobs(document_id, level_id, status);

-- 手账
CREATE TABLE handbooks (
    id           BIGSERIAL PRIMARY KEY,
    document_id  BIGINT NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    user_id      BIGINT NOT NULL REFERENCES users(id),
    level_id     VARCHAR(32) NOT NULL,
    title        TEXT,
    theme        VARCHAR(32) DEFAULT 'ruled_paper',  -- 横线纸/方格纸/答题卡
    layout_mode  VARCHAR(32) DEFAULT 'overlay',      -- overlay(原文叠加)/reflow(手账重排)
    stats        JSONB,                              -- {words:32, patterns:7, ...}
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE(document_id, level_id, theme, layout_mode)
);

-- 标注
CREATE TABLE annotations (
    id          BIGSERIAL PRIMARY KEY,
    handbook_id BIGINT NOT NULL REFERENCES handbooks(id) ON DELETE CASCADE,
    block_id    BIGINT NOT NULL REFERENCES document_blocks(id) ON DELETE CASCADE,
    type        VARCHAR(32) NOT NULL,
    start_offset INT NOT NULL,
    end_offset   INT NOT NULL,
    payload     JSONB NOT NULL,          -- 音标/释义/讲解/用途/颜色等
    priority    SMALLINT DEFAULT 50,
    source      VARCHAR(16) DEFAULT 'llm', -- llm/rule/user
    confidence  REAL,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_ann_handbook ON annotations(handbook_id, block_id, start_offset);

-- 生词本
CREATE TABLE vocab_items (
    id            BIGSERIAL PRIMARY KEY,
    user_id       BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    lemma         VARCHAR(64) NOT NULL,
    surface       VARCHAR(64),
    phonetic      VARCHAR(64),
    gloss_zh      TEXT,
    level_tag     VARCHAR(8),
    source_doc_id BIGINT REFERENCES documents(id) ON DELETE SET NULL,
    context_sent  TEXT,
    ease          REAL DEFAULT 2.5,           -- SM-2 参数
    interval_days INT DEFAULT 0,
    repetitions   INT DEFAULT 0,
    due_at        DATE,
    mastery       SMALLINT DEFAULT 0,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE(user_id, lemma)
);
CREATE INDEX idx_vocab_due ON vocab_items(user_id, due_at);

-- 用户自带模型密钥（加密存储）
CREATE TABLE user_llm_keys (
    id           BIGSERIAL PRIMARY KEY,
    user_id      BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    provider     VARCHAR(32) NOT NULL,
    label        TEXT,
    base_url     TEXT,
    key_cipher   BYTEA NOT NULL,       -- AES-256-GCM 加密
    key_last4    CHAR(4),
    model_map    JSONB,                -- {"annotate":"...","vision":"...","fast":"..."}
    is_default   BOOLEAN DEFAULT false,
    verified_at  TIMESTAMPTZ,
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 句型模板库（辅助匹配 + 向量检索相似句）
CREATE TABLE sentence_patterns (
    id           BIGSERIAL PRIMARY KEY,
    name         TEXT NOT NULL,
    structure    TEXT NOT NULL,        -- "Not until + 时间状语 + 助动词 + 主语 + 谓语"
    regex_hint   TEXT,
    usage_tags   TEXT[],
    min_level    VARCHAR(32),
    example      TEXT,
    embedding    VECTOR(1024)
);
CREATE INDEX idx_pattern_vec ON sentence_patterns USING ivfflat (embedding vector_cosine_ops);

-- LLM 调用日志
CREATE TABLE usage_logs (
    id           BIGSERIAL PRIMARY KEY,
    user_id      BIGINT REFERENCES users(id) ON DELETE SET NULL,
    job_id       BIGINT REFERENCES analysis_jobs(id) ON DELETE SET NULL,
    provider     VARCHAR(32),
    model        VARCHAR(64),
    task         VARCHAR(32),
    tokens_in    INT,
    tokens_out   INT,
    latency_ms   INT,
    ok           BOOLEAN,
    error_code   VARCHAR(64),
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_usage_user_time ON usage_logs(user_id, created_at DESC);
```

## 9. 大模型（LLM）接入方案

### 9.1 抽象接口

```python
class BaseLLMProvider(ABC):
    name: str

    @abstractmethod
    async def chat(self, messages: list[Message], *, model: str,
                   json_schema: dict | None = None,
                   temperature: float = 0.2,
                   max_tokens: int = 4096) -> LLMResult: ...

    @abstractmethod
    async def chat_stream(self, messages, *, model, **kw) -> AsyncIterator[str]: ...

    @abstractmethod
    async def vision(self, image: bytes, prompt: str, *, model: str) -> str: ...

    @abstractmethod
    async def health_check(self) -> bool: ...
```

### 9.2 任务 → 模型路由表

| 任务 | 能力要求 | 推荐配置 |
|---|---|---|
| 分句 / 词性 / 词形还原 | 无（本地） | spaCy 本地模型，成本 0 |
| 简单翻译（词义） | 低 | `fast` 档（如 Qwen-Turbo / DeepSeek-V3 / gpt-4o-mini） |
| 语法标注与讲解 | 高（需语言教学理解） | `annotate` 档（如 DeepSeek-V3 / GPT-4o / Claude Sonnet / Qwen-Max） |
| 句型提取与用途分类 | 高 | `annotate` 档 |
| 图片 / 图表理解 | 多模态 | `vision` 档（GPT-4o / Qwen-VL-Max / Gemini） |
| 长难句图解 | 中高 | `annotate` 档 |

用户 BYOK 时可在设置里为每个任务档位指定具体模型：

```json
{
  "fast":     "deepseek-chat",
  "annotate": "deepseek-reasoner",
  "vision":   "qwen-vl-max"
}
```

### 9.3 供应商适配清单

| 供应商 | 接入方式 | 备注 |
|---|---|---|
| OpenAI | 官方 SDK / OpenAI 兼容 | `response_format: json_schema` 支持结构化输出 |
| Azure OpenAI | 同 OpenAI，改 `api-version` 与 endpoint | 企业合规友好 |
| DeepSeek | OpenAI 兼容 | 性价比高，中文讲解质量好，国内直连 |
| 通义千问（DashScope） | OpenAI 兼容模式 | 有 VL 多模态 |
| 智谱 GLM | OpenAI 兼容 | 有 GLM-4V |
| Anthropic Claude | 官方 SDK（tool use 做结构化） | 长文本与教学讲解强 |
| Google Gemini | 官方 SDK | 多模态强，长上下文 |
| Groq | OpenAI 兼容 | 极低延迟，适合 fast 档 |
| Ollama / vLLM（本地） | OpenAI 兼容（`http://localhost:11434/v1`） | 完全离线、零成本，适合隐私敏感用户 |
| 任意 OpenAI 兼容端点 | 用户填 `base_url` + `api_key` | 覆盖自建网关、One-API 中转 |

### 9.4 密钥安全

- 用户密钥使用 **AES-256-GCM** 加密后存库，主密钥来自环境变量 / KMS，**不落盘明文**。
- 日志中一律脱敏（只保留后 4 位）。
- 每个请求独立构造 Provider 实例，密钥不进入全局变量、不写入日志、不返回前端。
- 支持"使用一次后不保存"模式。

### 9.5 可靠性设计

```
调用 LLM
  ├─ 超时：connect 5s / read 60s（长文分段）
  ├─ 重试：指数退避 3 次（仅对 429/5xx/超时）
  ├─ 降级链：主模型 → 备用模型 → 备用供应商 → 纯规则标注
  ├─ 熔断：某供应商 5 分钟内失败率 > 50% → 临时剔除 10 分钟
  └─ 幂等：同一 (job_id, block_id, task) 结果落库缓存，重试不重复计费
```

### 9.6 提示词版本管理

- 目录：`llm/prompts/{task}/v{n}.jinja`，`manifest.yaml` 记录当前生效版本。
- 每次发布提示词必须跑**回归测试集**（见 16.3），通过率下降超过 3% 则拒绝发布。
- 缓存键包含 `prompt_version`，提示词更新后旧缓存自动失效。

### 11.2 手绘质感实现（"涂改"美学）

纯 CSS/SVG 也能做出手写感，无需图片素材：

| 效果 | 实现 |
|---|---|
| 荧光笔 | `background: linear-gradient(180deg, rgba(255,224,102,0) 52%, #FFE066 52%, #FFE066 92%, rgba(255,224,102,0) 92%)` + `border-radius` 微随机<br>⚠ 两个坑：① **不要用 `var(--hl)`** 这类通用变量名，宿主环境会重定义它（见 §11.5）；② **不要用 `transparent`**，它就是 `rgba(0,0,0,0)`，丢掉 alpha 的渲染路径会把它变成**不透明纯黑**，即「黑色横杠」 |
| 手绘圆圈 | SVG `<ellipse>` + `stroke-linecap:round` + `filter: url(#roughen)`（feTurbulence 位移滤镜） |
| 波浪线 | SVG `<path>` 生成正弦波，振幅 ±1.5px，周期 8px |
| 手写下划线 | SVG 直线 + 尾部轻微上扬 + 透明度 0.85 |
| 便利贴 | `rotate(-1.2deg)` + `box-shadow` + 顶部胶带伪元素 |
| 涂改修正 | `<del>` 加 `text-decoration-thickness` + 上方 `<span>` 绝对定位红色文字 |

SVG 通过 `rough.js`（前端库）或服务端 Python `svgwrite` + 抖动算法生成，保证每次渲染的"随机感"一致（用 `block_id` 作为随机种子）。

### 11.5 CSS 交付的两个陷阱（都会被咬）

手账 HTML 是**交给外部环境渲染**的（浏览器、PDF 引擎、预览面板、被嵌入的 iframe），
所以「在我这儿是对的」不等于「在用户那儿是对的」。有两个坑各咬过一次：

**① 通用 CSS 变量名会被宿主重定义**

`--hl` / `--paper` / `--ink` / `--note` 这种名字太通用，宿主的主题样式表（深色模式、
组件库、预览面板）会顺手把它们设成自己的值。现象是**一部分正常一部分诡异**：
同一个 `:root` 里 `--paper` 显示正确（纸色 `#fdfaf3` 一个像素不差），
而 `--hl` 变成了黑色 —— 这就说明不是我们的值写错了，是**外围环境覆盖了这个名字**。

> 对策：所有变量加项目前缀（`--sp-hl` / `--sp-paper`），并且**关键视觉（荧光笔）直接写字面量**，
> 一点不依赖变量。回归断言：产物里任何 `var()` 引用的名字都必须以 `--sp-` 开头。

**② `transparent` 就是 `rgba(0,0,0,0)` —— 黑配零透明**

它不是一个「无色」关键字，而是**透明黑**。只要某条渲染路径丢掉 alpha 通道
（打印导出、SVG 栅格化、某些合成器把 rgba 降级成 rgb），
`transparent` 立刻变成**不透明纯黑** —— 于是荧光笔变成压在词上的黑色实心横杠。
这类路径**确实存在**：项目里 `probe_pagination.py` 量的所有 `.note` 都是零面积矩形，
证明 Chrome `print-to-pdf` 真的会丢元素、会走非标准的渲染路径。

> 对策：渐变里的透明端写成**与色带同色族的零透明**（`rgba(255,224,102,0)`）。
> 这样即使 alpha 被丢掉，得到的也只是**看不见**，而绝不会是一块黑。
> 回归断言：样式里任何渐变不许出现 `transparent`、不许出现不透明黑。

这两条都写进了 `scripts/check_render.py` 的「黑条回归」（正向 13 条 + 反向 4 条）。
反向那 4 条是**故意把旧实现贴回去**，要求审计必须报警 ——
一条永远不会失败的断言等于没写。

## 12. 安全、合规与版权

### 12.1 文件与数据安全

| 风险 | 措施 |
|---|---|
| 恶意文件上传 | 类型白名单 + Magic Number 校验 + 大小限制；解析在**独立沙箱容器**内进行，禁网、限内存/CPU、超时强杀 |
| 路径穿越 | 存储 key 由服务端生成（UUID），绝不用用户文件名 |
| XSS（文档内容注入） | 渲染前对文本做 HTML 转义；Markdown 用白名单渲染器；CSP 头 |
| SSRF（BYOK 的 base_url） | 禁止访问内网段（私有 IP 黑名单）；仅允许 https |
| 密钥泄露 | AES-256 加密存储；日志脱敏；不返回前端 |
| 越权访问 | 所有资源查询强制带 `user_id` 条件；对象存储用带签名的临时 URL |
| 数据删除 | 用户删文档 → 软删 + 30 天后物理清理（含对象存储） |

### 12.2 版权提示

- 上传页显著提示：**"请仅上传您有权使用的材料，本工具仅用于个人学习。"**
- 平台不存储、不传播受版权保护的公开内容；用户上传内容默认私有。
- 分享功能（P2）默认关闭，开启时提示用户自行确认版权责任。
- 免费用户导出 PDF 可加水印（可选开关）。

### 12.3 内容合规

- 接入内容审核（文本 + 图片），拦截违规内容。
- 生成内容（批注、例句）做二次审核抽样。
- 面向未成年人的功能需符合相关法律法规要求。

### 12.4 隐私

- 明确隐私政策：上传文档**不用于模型训练**、**不对外共享**。
- 提供"仅本地处理"模式（配合 Ollama，数据不出本机）。

### 16.2 标注质量评估（最重要）

**建黄金数据集**：请 2 名英语教师对 20 篇不同难度文章（覆盖 6 个等级）做人工标注，形成 ground truth。

评估指标：

| 指标 | 定义 | 目标 |
|---|---|---|
| 词汇圈选精确率 | 圈对的词 / 圈出的词 | ≥ 0.85 |
| 词汇圈选召回率 | 圈对的词 / 应圈的词 | ≥ 0.80 |
| 语法标注准确率 | 结构判定正确 / 总标注 | ≥ 0.88 |
| 语法讲解可用性 | 人工 5 分制评分均值 | ≥ 4.0 |
| 句型用途分类 | 分类正确比例 | ≥ 0.80 |
| 标注密度符合度 | 与画像要求一致的段落比例 | ≥ 0.95 |
| 偏移定位正确率 | `text[start:end] == target` | = 1.00（硬约束） |

### 16.3 LLM 回归测试集

- 固定 50 篇文章 × 6 等级 = 300 个用例。
- 每次改提示词 / 换模型 → 全量跑，输出指标对比表。
- 通过率下降 > 3% 阻断发布。
- 同时记录 token 消耗，防止"为了准确率疯狂加提示词"。

### 16.4 边界用例清单

- 加密 PDF、损坏 PDF、0 字节文件
- 纯图片 PDF（无文字层）
- 双栏/三栏排版
- 中英混排
- 超长单句（> 200 词）
- 特殊字符、emoji、数学符号、LaTeX 残留
- 表格跨页
- 页眉页脚含章节名（易被误判为正文）
- 用户切换等级时任务并发冲突

## 17. 风险与对策

| # | 风险 | 影响 | 概率 | 对策 |
|---|---|---|---|---|
| R1 | LLM 返回 JSON 不规范导致解析失败 | 高 | 中 | 三重输出约束 + 兜底正则 + 规则降级；重试策略 |
| R2 | 标注偏移量漂移（模型给的 offset 不准） | 高 | 高 | **后端二次定位校验**，diff 模糊匹配修复，失败丢弃 |
| R3 | 标注过密，体验变差 | 高 | 中 | 密度控制算法 + 黄金数据集验证 + 用户反馈开关（"标记太多/太少"） |
| R4 | 等级词表质量不足，圈错词 | 高 | 中 | 多源词表融合（CET 官方 + Oxford + COCA 频次）+ 人工抽检 |
| R5 | OCR 对扫描件识别率低 | 中 | 中 | RapidOCR 中英混合模型 + 图像预处理（去噪/纠偏/二值化）+ 用户手动修正入口。**已实装**：整行识别失败的碎片由 `layout.is_garbled()` 判定并丢弃，解析结果里报告丢弃行数 |
| R6 | 大模型成本失控 | 高 | 中 | 预筛、缓存、批量、BYOK、配额限流、成本告警 |
| R7 | 版权争议 | 中 | 中 | 显著提示 + 默认私有 + 不提供公开内容库 |
| R8 | 渲染保真度不足（PDF 分页错乱） | 中 | 中 | Playwright 打印 CSS 精细化 + 视觉回归测试 |
| R9 | 供应商 API 不稳定/限流 | 中 | 高 | 多供应商容灾 + 熔断 + 降级 |
| R10 | 长文档超上下文窗口 | 中 | 中 | 分段处理 + 地图-归约式汇总 |
| R11 | 用户上传违规内容 | 中 | 低 | 内容审核 + 举报机制 |
| R12 | 手写字体版权 | 低 | 低 | 只用 OFL 开源字体（LXGW WenKai / Caveat / Kalam） |
